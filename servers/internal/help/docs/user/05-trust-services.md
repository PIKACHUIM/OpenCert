# 证书链、CRL 与 OCSP

门户 **信任服务** 页面列出平台对外公开的 CA，以及每个 CA 的下载与查询地址。

## 证书链

部署证书时需要同时安装签发它的中间 CA 与根 CA，否则客户端可能提示「证书链不完整」或「不受信任」。

- **下载 CA 证书（DER）**：地址形如 `/ca/<CA 标识>`，可直接导入操作系统或浏览器信任库；
- **下载证书链（PEM）**：包含该 CA 及其上级 CA，适合配置到 Web 服务器（如 Nginx 的 `ssl_certificate` 需拼接站点证书 + 证书链）。

页面同时显示 CA 证书的 **SHA-256 指纹**，导入前请核对，防止被替换。

## CRL（证书吊销列表）

- 地址形如 `/crl/<CA 标识>`，若平台配置了自定义路径则为 `/pki/crl/<路径>`；
- CRL 由平台定期重新生成，应用应按 CRL 中的「下次更新时间」重新下载。

## OCSP（在线证书状态协议）

- 地址形如 `/ocsp/<CA 标识>` 或 `/pki/ocsp/<路径>`；
- OCSP 是给客户端程序调用的协议接口，**不是网页**，在浏览器中直接打开不会显示内容；
- 证书被吊销后，OCSP 会立即返回 revoked 状态。

## 什么时候需要这些地址

- 自建系统校验用户证书是否有效（如企业 VPN、单点登录）；
- 签名验签系统需要校验签名证书状态；
- 平台签发的证书中已内置 CRL 与 OCSP 地址，大多数标准客户端会自动使用，一般无需手工配置。

如果页面未列出您需要的 CA，说明该 CA 未对外公开，请联系平台管理员。
