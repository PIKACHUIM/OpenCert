# 身份认证审核与自动审核接口

入口：**证书颁发 → 身份认证审核**，两个选项卡。

## 一、待审核（人工）

审核队列包含两类对象：

| 对象 | 进入队列的条件 | 通过后的效果 |
|---|---|---|
| 主体信息 | 字段中存在「人工审核」的字段（且无字段要求实名接口时优先走人工） | 状态变为已通过，按主体模板的有效期生效 |
| 扩展信息 | 扩展模板中该类（域名/邮箱/IP）的验证方式为「人工审核」 | 状态变为已验证，按该类策略的有效期生效 |

操作与要点：

- 「通过」直接放行；「驳回」需填写原因，原因会展示给用户，用户修改后可重新提交；
- 审核通过时按模板**有效期**写入过期时间（如 7d/30d/365d，`0` 表示长期有效）；
- 过期后用户需重新提交/重新验证，期间不能用于证书申请；
- 管理员也可对「待实名认证（verifying）」的主体信息直接人工放行（用于第三方接口不可用时的兜底）。

## 二、自动审核（认证接口）

### 内置验证方式（无需配置）

| 类型 | 验证方式 | 说明 |
|---|---|---|
| 域名 | DNS TXT / HTTP 文件 / TLS-ALPN | 由扩展信息模板按类型启停；TLS-ALPN 遵循 RFC 8737 |
| 邮箱 | 邮箱验证码 | 6 位数字，15 分钟有效，连续输错 5 次需重新发送 |
| IP | HTTP 文件 | 同域名 HTTP 方式 |

### 认证接口（插件式）

「新增认证接口」支持两类：

**邮件发送（email）**

| 驱动 | 必填配置 |
|---|---|
| SMTP | SMTP 服务器、端口（587/25/465）、用户名、密码/授权码、发件地址、发件人名称 |
| Resend | API Key、发件地址（需为 Resend 已验证域名下的地址），可选自定义 API 地址 |

- 保存后可用「测试」向指定邮箱发送测试邮件验证连通性；
- 密钥以平台主密钥加密存储（`config_enc` 使用 AES-256-GCM），编辑时显示为 `******`，保持不变即保留原值；
- 在**扩展信息模板**的邮箱策略中选择该接口；未指定时使用系统 SMTP 配置。

**实名认证（identity）**

| 驱动 | 状态 | 说明 |
|---|---|---|
| 通用实名回调（webhook） | 可用 | 平台跳转到您的实名页面，完成后由对方回调本平台 |
| 支付宝身份验证 | 插件位（未接入） | 需商户资质与官方接口联调，当前可通过通用回调适配 |
| 微信/腾讯云实名核身 | 插件位（未接入） | 同上 |

通用实名回调对接规范：

1. 平台生成会话后跳转到 `redirect_url`，并追加参数：
   - `session`：平台会话 UUID；
   - `callback`：回调地址 `{平台地址}/api/identity/callback/{providerUUID}`；
   - `return`：完成后回跳的前端地址；
   - `expires`：会话过期时间戳（默认 30 分钟）。
2. 实名服务完成核验后，向 `callback` 发送 **POST JSON**：

   ```json
   {
     "session": "平台会话 UUID",
     "status": "passed",
     "message": "可选说明",
     "timestamp": 1760000000
   }
   ```

   `status` 为 `passed` 表示通过，其他值视为未通过；
3. 请求头必须携带 `X-Signature: hex(HMAC-SHA256(secret, 原始请求体))`，`secret` 为接口配置中的「回调签名密钥」；时间戳与服务端相差超过 10 分钟会被拒绝；
4. 校验通过后平台自动放行对应主体信息（记为 `identity:{providerUUID}` 审批人）；未通过则写入驳回原因，用户可重新发起。

### 在模板中引用

- **主体模板**：字段验证方式选「自动接口（实名认证）」并选择实名认证接口；模板级「审核/认证有效期」决定通过后的有效期。若存在自动字段但未选择接口，系统会将该主体信息降级为人工审核，避免用户卡死。
- **扩展信息模板**：按域名/邮箱/IP 分别设置启用、验证方式（人工/自动/免验证）、可用方法组合与验证有效期；邮箱类可指定使用哪个邮件接口。
