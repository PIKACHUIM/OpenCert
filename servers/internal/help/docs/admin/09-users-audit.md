# 用户、角色与审计

## 1. 角色权限

| 角色 | 权限范围 |
|---|---|
| 超级管理员 `super_admin` | 全部权限 |
| 管理员 `admin` | 全部业务配置：CA、模板、商品、订单、支付插件、用户、站点设置、服务配置 |
| 操作员 `operator` | 审核主体信息与证书申请、查看全局证书与审计日志 |
| 普通用户 `user` | 购买、申请、使用自己的证书与智能卡 |
| 只读 `readonly` | 只能查看，所有写操作被拒绝 |

最小权限原则：审核人员使用 `operator`，财务人员如需确认到账使用 `admin`，避免日常使用 `super_admin`。

## 2. 用户管理

入口：**系统管理 → 用户管理**。

- 创建用户：用户名（创建后不可改）、显示名称、邮箱、角色、初始密码（至少 8 位）；
- 编辑：显示名称、邮箱、重置密码；角色通过列表中的角色下拉框修改；
- 停用：停用后无法登录，已有数据保留；
- 登录连续失败 5 次会锁定 15 分钟。

## 3. 审计

| 位置 | 内容 |
|---|---|
| 系统管理 → 操作日志审计 | 用户操作：下单、支付、开卡、提交申请、导出、退款申请等 |
| 平台管理 → 证书审计日志 | 高敏操作：私钥下发、确认到账、管理员取消订单、解锁/删除卡片、公开 CA 等；采用链式哈希，页面会提示完整性校验结果 |

证书审计日志完整性校验失败时，说明日志可能被篡改，应立即冻结数据库并排查。
