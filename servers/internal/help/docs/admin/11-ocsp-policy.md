# OCSP 响应服务与证书策略

## 一、OCSP 响应服务（证书服务 → 证书OCSP服务）

### 与「证书吊销服务」的区别

| 能力 | 证书吊销服务 | 证书OCSP服务（本页） |
|---|---|---|
| 签名者 | 每个 CA 用自身私钥签名 | 单个签名证书，可服务多个 CA |
| 地址 | `/ocsp/{caUUID}`、自定义 `/pki/ocsp/{path}` | `/ocsp/r/{path}` |
| 适用 | 单 CA、内部使用 | 对外统一 OCSP 入口、委托签名场景 |

### 配置步骤

1. 点击「新增响应服务」，填写**服务名称**与**路径**（仅小写字母、数字、短横线，如 `unified`）；
2. 选择**签名证书类型**：
   - **CA 自身私钥签名**：兼容性最好，选择负责的任一 CA 即可；
   - **平台内证书**：推荐使用由 CA 签发的、带 `id-kp-OCSPSigning`（1.3.6.1.5.5.7.3.9）扩展密钥用法的**OCSP 委托签名证书**；该证书的私钥必须存放在平台内（云端生成），响应中会附带该证书供依赖方校验委托关系。
     若使用完全独立的响应者证书（非委托），依赖方需要显式信任该证书。
3. 选择**负责响应的 CA**（可多选）：只有列表内 CA 签发的证书会被响应，其他 CA 返回 `unauthorized`；
4. 设置**下次更新时间**（响应中声明的状态有效期）与**未登记序列号策略**：
   - `unknown`（默认，RFC 6960 推荐）：平台未签发的序列号返回 unknown；
   - `good`（宽松）：兼容在平台外签发但需要本响应服务的证书。
5. 保存后页面显示完整响应地址，例如 `https://ca.example.com/ocsp/r/unified`。

### 客户端如何使用

- POST 方式：`Content-Type: application/ocsp-request`，请求体为 DER；
- GET 方式：`/ocsp/r/{path}/{base64url(DER)}` 或 `?req=base64`；
- 证书的 AIA 扩展（颁发模板 → 证书拓展模板 → OCSP 服务器）填入上面的地址即可被浏览器/客户端自动发现。

### 排障

| 现象 | 原因与处理 |
|---|---|
| 返回 `unauthorized` | 查询的证书颁发者（按 IssuerKeyHash 匹配）不在该服务的「负责的 CA」列表中 |
| 返回 `unknown` | 该序列号在平台内既无签发记录也无吊销记录；若证书确实由本平台签发，请检查 CA 是否选对 |
| 返回 `internal error` | 签名证书不可用（已删除、已吊销、私钥不在平台内或已过期），在列表中编辑并重新选择 |

## 二、证书策略管理（证书服务 → 证书策略管理）

用于发布证书策略（CP）、证书实践声明（CPS）、服务条款等文档，每个策略是一个独立页面：

- 访问地址：`/policy/{路径}`（如 `/policy/cps`）；
- 内容格式：Markdown（推荐）或 HTML；
- HTML 以严格 CSP 返回（禁止脚本），适合已有排版好的文档；
- 勾选「在官网信任服务中公开」后，会出现在门户「信任服务」页的**证书策略与合规文档**栏目中。

### 建议包含的内容（生产发布要求）

1. 适用证书类型与 OID；
2. 身份验证要求（个人/企业需提交的材料与验证方式）；
3. 域名/邮箱/IP 所有权验证方法；
4. 签发、续期、吊销与退款政策；
5. 密钥保护方式（云端托管、PIN/PUK/Admin Key、HSM/存储区域）；
6. 责任限制、隐私与联系方式。

### 与证书的关联

在「证书模板 → 证书拓展模板」的证书策略/CPS URI 中填入 `/policy/cps` 地址，签发出的证书即可携带该 CPS 引用，便于审计与合规检查。
