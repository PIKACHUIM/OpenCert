# CA、证书模板与三层配置

## 一、证书颁发机构（证书颁发管理 → 证书颁发机构）

创建 CA 和签发证书使用同一套表单，区别只是"签出来的证书本身是不是 CA"。

1. **创建 CA**：选择 CA 类颁发模板 → 选择上级 CA（自签根 CA 留空；中间 CA 选一个已有 CA）→ 填写主体 → 选择密钥算法与签名哈希 → 设置生效/失效时间 → 选择存储区域（本地加密 / HSM / TPM）；
2. **导入 CA**：
   - 证书 + 私钥：支持 PEM、PKCS#8、PKCS#12（含密码），同样需要选择存储区域；
   - 仅证书：作为外部 CA 使用，只参与证书链，不用于签发；
3. **内置模板**：系统里没有任何 CA 类颁发模板时，会自动创建"根 CA 证书""中间 CA 证书"两个模板，以及 CA 专用的密钥用途模板（证书签名 + CRL 签名）；
4. **对外发布**：勾选公开后，该 CA 出现在门户「信任服务」中，可下载证书链；
5. **吊销与 CRL**：吊销证书后会自动写入 CA 的吊销列表；CRL 刷新间隔在「证书服务管理 → 证书吊销服务」中按 CA 配置；
6. **OCSP**：单 CA 场景使用该 CA 的 OCSP 地址；多 CA 统一入口请使用「证书服务管理 → OCSP 响应服务」。

> 算法约束：SM2 只能配 SM3；SM2 CA 只能签发 SM2 证书；SM2 证书不提供 PKCS#12 导出。

## 二、三层职责划分（重要）

平台把"怎么签 / 怎么申请 / 怎么卖"拆成三层，避免同一参数在多处重复配置：

| 层 | 位置 | 负责 |
|---|---|---|
| **颁发模板**（Issuance Template） | 证书模板管理 → 颁发模板 | 唯一的技术配置来源：候选 CA 与默认 CA、是否 CA 证书与路径长度、有效期选项与默认值、允许的密钥算法与签名哈希、关联的密钥用途 / 证书扩展 / 密钥存储 / 主体 / 扩展信息模板 |
| **开通模板**（Apply Template） | 证书模板管理 → 证书开通模板 | 只管业务规则：关联颁发模板、是否需要审批、是否允许续期、可申请方式（订单 / 自助 / 订阅）、启用、说明；CA、有效期、算法只读展示并标注"继承自颁发模板" |
| **商品规格**（SKU） | 销售管理中心 → 销售商品管理 | 只管售卖：价格、库存、购买数量、证书有效期、可选算法、交付方式、域名 / 邮箱 / IP 限制；有效期与算法只能在颁发模板允许的范围内选择，保存时即校验 |

价格与库存只存在于规格上（颁发模板上的历史价格字段已不再使用）；SNA 数量限制只在规格上（扩展信息模板不再限制数量）。

商品与开通模板的引用关系：**规格 → 开通模板 → 颁发模板**。云智能卡类商品的规格只需任选一个开通模板占位（不会用于证书申请）。

## 三、主体模板（证书模板管理 → 主体模板）

定义证书主体字段的填写与验证规则，字段名从预置列表选择（CN/O/OU/C/ST/L/STREET/PostalCode/SerialNumber/E/UID/Title/...）。

每个字段可配置：

| 配置 | 说明 |
|---|---|
| 必填 | 不填则跳过该字段 |
| 长度范围 | 最短/最长字符数（最长留空默认 128） |
| 格式 | 预置格式：国家代码 / 邮箱 / 域名 / 纯数字 / 统一社会信用代码；也可填自定义正则 |
| 验证方式 | 人工审核 / 自动接口（实名认证）/ 免验证 |
| 派生 | 空 / 取自第一个域名 / 第一个邮箱 / 第一个 IP。派生字段由扩展信息自动推导，**不显示给用户、无需验证** |
| 默认值、填写提示 | 表单辅助 |

模板级配置：

- **审核/认证有效期**：`1d/7d/30d/365d`、`12h` 等（`0` 表示长期有效）；通过后按此计算过期时间；
- **实名认证接口**：字段中存在「自动接口」时必选。

典型配置：

- 企业 OV：`CN`（人工）、`O`（人工）、`C`（免验证，默认 CN）、`SERIALNUMBER`（人工，统一社会信用代码格式）；
- 域名 DV：仅 `CN` 派生自第一个域名 —— 此时申请向导会跳过主体信息步骤。

## 四、扩展信息模板（证书模板管理 → 扩展信息模板）

按**域名 / 邮箱 / IP** 三类分别配置：

| 配置 | 说明 |
|---|---|
| 是否允许 | 关闭则该证书不接受此类扩展信息 |
| 验证方式 | 人工审核 / 自动验证 / 免验证 |
| 验证接口 | 从「身份认证审核」中已启用的接口里选择（域名类内置 DNS TXT、HTTP 文件、TLS-ALPN；邮箱类选邮件接口） |
| 验证有效期 | 如 `1d/7d/30d/365d`；过期后需重新验证 |

> 验证接口的解析服务器、记录前缀、端口、超时等参数在「身份认证审核」里配置一次即可，所有引用它的模板共享。

> 单张证书允许的域名/邮箱/IP 数量、是否允许通配符、IPv4/IPv6、邮箱与域名后缀限制，均配置在**商品规格**上，见《商品、订单与销售流程》。

## 五、其他模板

四类模板都支持新建与编辑，删除前会检查是否被颁发模板引用，仍被引用时不允许删除。

- **密钥用途模板**：密钥用法（数字签名、密钥加密、证书签名、CRL 签名等位）+ 扩展密钥用法（服务器认证、客户端认证、代码签名、邮件保护、时间戳、OCSP 签名）；CA 证书必须包含证书签名与 CRL 签名；
- **证书拓展模板**：CRL 分发点、OCSP 服务器、AIA 颁发者、CT 服务器、EV 策略 OID；证书策略/CPS 地址可引用「证书策略管理」中发布的策略页面；
- **密钥存储模板**：存储区域、密钥生成位置（服务端 / 用户自带 CSR / 智能卡内生成）、下发方式（文件下载 / 云端智能卡 / 实体卡 / 虚拟卡）、下载格式、虚拟卡安全等级、是否允许重新导入、云端备份、重新下发次数（-1 表示不限）；
- **自定义 OID**：供证书拓展模板引用（扩展密钥用途、主体字段、EV 策略、ASN.1 扩展）；可设置 ASN.1 类型与是否标记为关键扩展。

## 六、配置检查清单（上线前）

1. 每个对外商品：规格 → 开通模板 → 颁发模板链路完整且均处于启用状态；
2. 开通模板已绑定主体模板与扩展信息模板（或明确使用 DV 简化流程）；
3. 主体模板中「自动接口」字段已选择可用的实名认证接口；
4. 扩展信息模板中邮箱策略已指定邮件接口（或确认系统 SMTP 可用）；
5. 规格的单张证书有效期与颁发模板允许的有效期列表一致（订阅套餐保存时会强校验）；
6. OCSP/CRL 地址已填入证书拓展模板，并在信任服务中心可访问。
