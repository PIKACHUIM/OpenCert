## 二、关键问题分析（按严重程度排序）

### 2.1 架构层面问题

#### 问题 A：文档与代码版本不一致

- `11-ROADMAP.MD` 显示 Phase 9/10/11 为 ⬜ 待开始
- 但 `04-CHANGELOG-ROUND3.md` 声称 T1-T24 全部完成（92%）
- 路线图文档未同步更新，造成信息混乱

#### 问题 B：client-card 多用户架构未完全落地

- 需求明确要求"允许多账号登录管理"，但 client-card 前端只有 10 个页面
- 缺少多用户切换、云端同步、用户级数据隔离的完整实现

#### 问题 C：三组件联调测试缺失

- pkcs11-mock ↔ client-card ↔ server-card 的 E2E 联调测试
- 在 `11-ROADMAP.MD` 中标记为 ⬜，是上线前的关键阻塞项

## 五、额外建议

1. **考虑引入 OpenAPI/Swagger**：当前 API 文档是手写 Markdown，建议生成 OpenAPI 3.0 规范，前端可自动生成 TypeScript 类型
2. **数据库迁移工具化**：当前使用 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`，建议引入版本化迁移（如 `golang-migrate`）
3. **日志结构化**：建议统一使用 `slog`（Go 1.21+）替代 `log` 包，输出 JSON 格式日志
4. **配置热加载**：当前配置需重启服务，可考虑 `fsnotify` 监听配置文件变更
5. **Graceful Shutdown**：确保三组件都实现优雅关闭（`context.WithCancel` + `signal.NotifyContext`）
