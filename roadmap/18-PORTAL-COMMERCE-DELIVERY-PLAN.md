## 一、目标与已确认决策

### 1.1 产品目标

将当前偏管理工具的服务端升级为完整的产品服务平台：

**访客了解产品 → 注册/登录 → 选择规格 → 下单支付 → 申请与验证 → 审批签发/云卡开通 → 下载或绑定客户端 → 使用、续期与售后。**

完成标准不是“页面存在”或“接口返回成功”，而是用户购买的资源能够按照承诺交付并实际使用，管理员能够配置、审核、追踪和处理异常。

### 1.2 已确认，不再重复询问

| 决策 | 结论 | 落地约束 |
|---|---|---|
| 网站架构 | 同站分层 | 同一 `servers/front` SPA；`/` 为门户，`/console` 为控制台；共用服务端账号体系 |
| 商品模型 | 独立 `portal_products` | 商品与技术模板解耦；证书商品通过规格引用 `cert_apply_templates` |
| 支付方式 | 订单直付 + 保留余额 | 支持第三方渠道直接支付订单，也可使用已有余额；不强制先充值 |
| 下单身份 | 必须注册后下单 | 匿名仅浏览、比较、配置；创建订单、支付、申请与交付必须绑定真实用户 |

### 1.3 本次文档边界

- 本文是对上一轮方案的修订，不表示代码、数据库迁移、支付接入或硬件联调已经完成。
- 本次仅新增规划文档并补充目录入口，不修改业务代码，不运行部署、安装或数据库迁移。
- 已确认的四项决策保留；本文新增的数据模型细节、分期和默认视觉方向仍属于待确认提案。
- 现有设计技能足以支撑这一轮规划，不为写文档安装额外技能或引入运行时依赖。

## 二、对接报告带来的关键修订

### 2.1 从“商城加页面”调整为“交易与使用闭环”

| 上一轮方案中的假设 | 修订后的结论 |
|---|---|
| 已有订单、支付和审批，只需补门户 | 相关模块可复用，但存在定价信任、状态机、模板关联和资金一致性断点，必须一起修复 |
| 签发完成就是订单完成 | 分开记录支付、申请、签发和交付；应展示“待下载/待绑定/交付失败”，不能用一个成功页掩盖失败 |
| 云卡是介绍页和创建表单 | 云卡是可配置、可开通、可到期续费的资源；客户端发现、TOTP、PIN、签名必须纳入验收 |
| 所有交付都走证书和私钥下载 | 分成公开证书下载、可导出私钥交付、云端远程使用、设备制钥 CSR 回装四条路径 |
| 客户端需要补商城和后台页面 | 不复制；订单、付款、申请审核、商品配置留在服务端网站，客户端只做凭据使用与必要跳转 |
| 库存、有效期、数量补到模板即可 | 商品 SKU 承担销售规格；购买数量、域名数量、购买服务期、单张证书有效期必须分别建模 |
| 回调按 `CO`/`RC` 单号前缀分派即可 | 单号前缀仅便于识别；业务归属、渠道、金额、币种、商户与幂等均以持久化支付记录校验 |
| 云卡、CA/CRL/OCSP 下载中心放到可选尾期 | 属于用户原始核心需求，纳入完整版本验收；只有额外增强能力另行排期 |

| 范围 | 现状与风险 | 关键位置 |
|---|---|---|

### 2.3 对 `17` 报告的使用说明

保留报告原文作为独立分析材料，本文不回写其历史结论。实施时以下述精化解释为准：

1. 报告摘要称客户端 `ListCards` 检索为零，但源码中方法确实存在；准确问题是**方法已有，业务路径未调用**。
2. 报告对“订单支付完整”“ACME 完整”等总体描述不能视为生产可用证明；本文以具体调用链和验收结果为准。
3. `storage_methods` 和 `security_level` 是策略配置，不证明真实 HSM/TPM 能力。不能把“同步模板安全等级”直接变成“设备已获硬件安全保证”。
4. 未设置 PIN 的历史云卡目前存在免 PIN 分支；新购云卡必须有明确的 PIN 初始化和激活策略。
5. 同步中的 `allowInsecure=true` 表示允许 HTTP，不等于跳过 TLS 证书校验；生产统一关闭非 HTTPS 连接。
6. 普通 CSR 路径的软件制钥、导入 TPM 包装，与“设备内制钥且私钥从未离开硬件”不是同一交付能力。

## 三、职责划分：一个网站，三种使用场景

### 3.1 门户、用户控制台、运营后台、桌面客户端

| 功能 | 公开门户 | 用户控制台 | 运营后台 | 本地客户端 |
|---|---|---|---|---|
| 产品介绍、比较、报价 | 主要入口 | 返回选购 | 配置产品 | 浏览器跳转 |
| 下单、支付、退款 | 登录后进入收银台 | 我的订单与财务 | 全局订单、对账、退款审批 | 不复制交易模块 |
| 证书申请、验证、进度 | 引导入口 | 申请向导与待办 | 审核与异常处理 | 必要时生成 CSR，跳转查看申请 |
| 云卡开通 | 产品与规格选择 | 初始化、激活、续费 | 开通模板、配额、运营状态 | 拉取并绑定已开通云卡 |
| 证书与私钥交付 | 不开放匿名访问 | 下载、下发、交付记录 | 策略与异常审计 | 接收允许下发的材料、绑定本地密钥 |

**边界原则：服务端是身份凭据与交易事实的权威；客户端不充当商城、不镜像平台 RBAC、不新增远程设备管理体系。**

## 四、页面体验与视觉方向

### 4.1 首页：先讲用户收益，再讲技术

首页结构建议：

1. 顶部导航：证书产品、云端智能卡、信任服务、下载与帮助、登录/注册或控制台。
2. 首屏：用一句话解释“统一申请数字证书，并通过云端智能卡在设备上安全使用”；两个主入口为“选购证书”“了解云端智能卡”。
3. 产品入口：SSL/TLS、代码签名、邮件签名与加密、文档签名、云端智能卡。
4. 云卡说明：应用 → 本地客户端/驱动 → 云端卡的简洁示意，明确远程签名需要网络。
5. 使用步骤：选择产品、验证资料、获得证书、部署或绑定客户端。
6. 信任与支持：CA 链、CRL、OCSP、安装指南及支持入口。

不在首屏堆放 CA 管理、OID、端口号、数据库等后台术语；不写未经验证的兼容率、客户数量、签发时效或安全认证。

### 4.2 商品比较页

参考第一张图片的信息组织，而不是照搬示例价格与服务承诺：

- 对齐显示套餐名称、适用对象、实际起售价、计费单位、权益和主要限制。
- 支持分类、认证/用途等级、域名覆盖方式、交付方式筛选。
- 推荐套餐可以突出，但不同套餐必须有真实差异，不能只是不同名称。
- “每月折算价”必须同时展示完整购买周期和总价，不能把一次性多年付款误导为按月扣款。
- 无库存、暂不支持、未配置价格、未启用渠道均有明确状态；不能显示可点击但无法履约的购买按钮。

### 4.3 购买配置页

参考腾讯云购买页：左侧分组配置，右侧固定摘要；窄屏改为可展开摘要和不遮挡操作的底部结算栏。

- 证书：产品/验证等级 → 覆盖范围 → 服务期/证书有效期说明 → 算法 → 密钥与交付方式 → 购买数量。
- 云卡：套餐 → 可用区域 → 卡片数量/证书配额 → 服务时长 → 开通方式。
- 禁用不兼容的组合并解释原因；用户不应手填 CA UUID、模板 UUID 或存储区域 UUID。
- 改规格重新获取服务端报价；摘要显示单价、数量、周期、优惠（若有）、应付总额和报价失效时间。
- 注册/登录后恢复非敏感配置；密码、PIN、私钥、支付密码不得写入路由参数或浏览器草稿。

### 4.4 默认设计建议（尚未由用户确认）

- 品牌暂沿用 OpenCert，站点名称、Logo、主色、支持地址做成可配置；不假定已决定更名。
- 浅色、银灰底、深色文字、克制蓝色强调，采用精确排版与留白；不延续当前紫蓝渐变的后台宣传页。
- 首页采用非对称的文字与云卡示意布局；商品比较以可读、可比较优先，不为了视觉变化打乱规格对齐。
- 中文正文优先采用可本地部署的思源黑体/Noto Sans SC；拉丁标题与数字可配 Plus Jakarta Sans；不依赖外网字体才能正常显示。
- 门户与控制台共享品牌 token，但各用独立布局和密度；控制台保留 Ant Design 和既有主题能力，不全量重做管理表单。
- 动效只辅助导航、选中反馈与步骤切换；支持键盘、可见焦点、减少动态效果设置，错误不能只通过颜色表达。

## 五、商品、规格与开通模板

### 5.1 三层模型

**商品负责“卖什么”，SKU 负责“按什么规格和价格卖”，模板负责“技术上如何开通”。**

| 层级 | 主要职责 | 不应承担 |
|---|---|---|
| `portal_products` | 商品类型、名称、slug、介绍、比较卖点、排序、上下架、公开展示 | 直接指定底层签发参数或接收用户传来的价格 |
| `portal_product_skus` | 价格、币种、库存、购买上下限、时长、可选算法/交付组合、模板引用 | 任意脚本化开通或不受约束的 JSON 参数执行 |
| 证书申请模板 | 复用 `cert_apply_templates`，关联颁发模板、CA、验证和存储策略 | 官网装修、多个渠道重复维护商品价格 |
| 云卡开通模板 | 新增独立 `cloud_card_templates`，规定区域、配额、PIN策略、有效期与开通审批 | 伪装成证书申请模板或宣称未接入的 HSM |

证书链路：`商品 → SKU → cert_apply_templates → issuance_templates → CA / 主体 / 扩展 / KU / EKU / 密钥存储策略`。

云卡链路：`商品 → SKU → cloud_card_templates → 开通记录/订阅 → cards`。

SKU 与模板为引用关系；下单时保存经过服务端校验的版本快照。模板禁用、CA 过期/吊销等安全变化仍能阻断履约，不能因为持有旧快照就继续签发。

### 5.2 管理员可配置内容

- 商品类型：SSL、代码签名、邮件证书、文档签名、云卡；允许受控增加展示分类，不允许新增任意执行型业务类型。
- 展示：标题、副标题、说明、卖点、推荐标识、FAQ、排序、上下架时间。
- 价格：SKU 单价、币种、计费单位、周期；模板中的旧价格仅用于兼容历史入口，新商城以 SKU 为唯一销售价格源。
- 数量：总库存、限购数、单次最小/最大购买量；`-1` 表示不限库存，`0` 明确表示售罄。
- 时间：售卖窗口、订单支付期限、服务购买周期、单张证书有效期、申请权益到期时间。
- 开通：证书申请模板或云卡模板、是否人工审批、可交付方式、可用区域、续费与补发规则。
- 发布检查：模板完整、CA 可用、算法支持、交付链路可用、价格合法；失败时禁止上架并给出具体原因。

### 5.3 数量与时间的产品语义

- 买 5 张证书 = 5 份申请权益，可分别填写不同主体并查看各自进度；不是一份申请无限签发。
- 5 个 SAN 域名 = 一张证书覆盖范围，不等于买 5 张证书。
- 买 3 年服务不等于签发单张 3 年证书；服务周期与单次签发有效期分开，并按所用 CA 实际规则限制。
- 云卡服务有效期与卡内证书有效期互不替代；续费云卡不能自动延长证书，证书续期也不能自动续费云卡。
- 证书实际有效期受模板、CA 有效期和签发规则约束；不能简单把所有类别写死为一年。

### 5.4 真实能力与商品承诺

自建 CA 可完成私有 PKI 签发，但不自然获得浏览器、操作系统或文档软件的公开信任。商品应展示“私有信任/已具备依据的公开信任范围”。

DV/OV/EV 名称、策略 OID、代码签名 EKU、文档签名 EKU 不等于已经完成对应审核、兼容认证或公共信任接入。缺少真实上游与能力验证时，不上架对应承诺；展示样例不得进入真实付款。

## 六、订单与支付闭环

### 6.1 交易订单与技术申请分离

为同时覆盖证书和云卡，建议新增轻量通用交易主单 `portal_orders` 与明细 `portal_order_items`，**不把云卡购买硬塞进 `cert_orders`**。

- 交易主单统一金额、买家、支付与退款；明细保存 SKU、规格快照、数量与履约类型。
- 证书明细按购买数量建立受唯一约束保护的申请权益，可使用关联后的 `cert_orders` 承载每份证书工作流。
- 云卡明细建立订阅/开通记录，成功后关联实际 `cards`。
- 同一订单中按明细与份数跟踪履约，允许显示部分完成；初版页面仅支持“同一 SKU 多份直接购买”，暂不实现购物车与混合购物结算。
- 门户订单的付款事实只有一个权威来源；旧 `cert_orders` 不能再次冻结、扣款或通过旧 `PayOrder` 绕过新支付服务。

这是对上一轮“只扩展 `cert_orders`”的修正，原因是资源类型和数量语义不同，不是增加另一套独立商城。

### 6.2 正常流程

1. 匿名配置商品并查看报价；点击提交时要求注册/登录，TOTP 未完成不能下单。
2. 服务端根据 SKU、数量、版本和有效报价重新计算金额，创建订单及库存预留；下单不要求已有余额，也不自动冻结余额。
3. 收银台展示可用渠道与账户余额。初版每次选择“余额全额支付”或“第三方全额直付”，不做混合支付。
4. 余额支付：订单状态校验、余额条件扣减、流水和支付记录在同一数据库事务内完成。
5. 直付：创建关联订单的支付尝试，返回实际渠道的二维码或跳转地址；客户端页面轮询自有订单接口。
6. 服务端验证支付回调或主动向渠道查询确认后，原子记录付款、实销库存并生成可重试的履约任务。
7. 证书订单引导“立即申请”；云卡订单引导“初始化/激活”。免费 SKU 也经过同一订单与权益流程，支付来源明确标记为免费。

充值保留现有入口，仅负责充值到账；直付购买不得伪装成充值，否则会混淆退款、余额和履约账务。

### 6.3 回调与资金一致性要求

- 请求中不接受客户端指定应付金额、付款成功、订单状态、审批人或证书归属。
- 验签之外，还需校验渠道、商户标识、订单关联、金额、币种和交易状态；首版以 CNY 为默认，其他币种仅在金额单位转换和渠道均验证后启用。
- 使用支付尝试 ID、渠道交易号唯一约束、条件状态更新和事务确保幂等；多次点击与重复回调不能重复扣款/开通。
- 更换支付渠道会生成新的支付尝试，但同一订单只接受一笔有效结算；迟到的重复付款进入对账/退款，不能再次履约。
- 库存按 SKU 原子预留；待支付超时释放。迟到付款与取消/超时竞争时记录真实到账，按可履约性补偿或退款，不忽略资金事实。
- 回调成功只说明已记账，不代表证书签发成功。网络调用、CA 签发和设备交付不放在长事务内；持久任务负责重试与恢复。

### 6.4 退款与取消

| 场景 | 行为 |
|---|---|
| 未付款取消/过期 | 关闭订单、释放库存，不产生“退款成功”记录 |
| 付款后尚未申请/开通 | 按发布的退款规则审核；余额原路回余额，第三方原路退款 |
| 资料需要修改 | 进入“待补资料”，不立即退款或要求重新购买 |
| 最终无法颁发/开通 | 提供明确原因及退款入口，冻结后续履约 |
| 已部分履约 | 按明细计算可退款数量和金额，不能默认退全单 |
| 已签发/已使用资源 | 依据已公开规则处理，不能自动回库存并按未使用资源再次销售 |

退款状态必须区分“申请中、审核通过、渠道处理中、成功、失败”；**实际调用渠道并确认成功后**才显示原路退款成功。退款和消费必须防止余额负数、重复退回与累计退款超额。

## 七、友好的证书申请与审批

### 7.1 统一申请向导

| 步骤 | 用户体验 | 服务端规则 |
|---|---|---|
| 1. 选择权益 | 从订单直接进入，无需选择模板 UUID | 校验已付款、归属、剩余数量、申请期限 |
| 2. 填写资料 | 按商品显示域名、邮箱、个人/组织字段；可复用已有资料 | 根据模板生成字段规则，校验用途、数量和格式 |
| 3. 验证身份/所有权 | DNS/HTTP 指引、邮箱验证码、组织材料审核，显示当前待办 | 验证结果绑定用户、具体标识、模板要求和有效期 |
| 4. 密钥与交付 | 上传 CSR、云卡内制钥，或策略允许的文件交付 | 只开放已验证可用的方式，CSR 校验签名及算法 |
| 5. 确认提交 | 显示最终主体、SAN、算法、有效期、费用与交付目标 | 重新校验订单、材料、CA、模板与密钥绑定 |
| 6. 跟踪与领取 | 时间线显示待审、补资料、签发、下载/绑定结果 | 人工或自动审批均使用同一编排与审计链路 |

- 草稿服务端保存，刷新、退出和稍后登录可继续；不保存私钥、PIN、账号密码等敏感输入。
- DNS 指引提供记录名、类型、值、复制按钮、检测结果和常见错误；不能用“等待中”覆盖全部失败原因。
- 邮件证书不强制填写域名；DV 类型不无条件要求组织资料；代码/文档签名按用途与实际审核要求展示字段。
- 联系邮箱与证书 SAN 邮箱分别处理，不能把联系邮箱自动写入所有证书。
- CSR 不是可信的主体声明：申请内容与 CSR 字段要一致，最终主体、SAN、EKU 由服务端验证结果和模板约束决定。
- 设备内制钥模式验证 CSR 持有证明，但普通 CSR 本身不证明密钥位于硬件中；需要硬件承诺时另验设备能力和密钥证明。

### 7.2 状态分层

建议避免把所有状态塞进现有 `CertOrderStatus`：

| 对象 | 建议状态 |
|---|---|
| 支付 | 待支付、处理中、已支付、失败、关闭、退款中、部分退款、已退款 |
| 证书申请 | 草稿、待验证、待审核、待补资料、通过、拒绝、取消 |
| 签发任务 | 待签发、签发中、已签发、失败待重试 |
| 交付任务 | 待交付、处理中、已可领取/已交付、失败 |
| 云卡资源 | 待初始化、开通中、正常、暂停、到期、终止 |

订单页面根据子状态汇总，分别说明“已支付”和“资源已可用”。批准申请、签发证书、分配卡片、下载文件分别记录事件。

审核退回要保存具体理由与补充要求；重新提交保留历史版本。自动审批只省去人工点击，不跳过验证。重复批准或任务重试不得多发证书、多扣权益。

### 7.3 生命周期

- 续期创建新订单/新申请或消耗已购买服务期内的续期权益，不修改原证书内容冒充续期。
- 重签、补发与重新下载分开计数；是否重新验证按验证材料有效期与当前模板决定。
- 用户可在控制台发起吊销申请；正式吊销由受控服务执行，客户端只消费状态，不直接获得管理员吊销权限。
- 通知覆盖支付结果、待补资料、审核结果、签发/交付完成、即将到期与退款结果；控制台消息是主入口，邮件失败不能让订单状态丢失。

## 八、云端智能卡产品与开通

### 8.1 开通向导

1. 选择套餐、有效期和可用区域，购买或领取明确的免费权益。
2. 输入卡片名称，确认服务规格与远程使用要求。
3. 在安全初始化步骤设置卡 PIN；恢复凭据按策略生成/设置并引导安全保存。
4. 按模板自动开通，或进入人工审批；失败可重试，不重复建卡、不重复扣权益。
5. 控制台显示卡片信息、剩余配额、到期时间和“绑定客户端”指引。
6. 客户端登录云账号并完成 TOTP，列出本人云卡，选择后自动建立映射，无需手填 `cloud_card_uuid`。
7. 使用时输入卡 PIN，验证远程签名成功；本地仅同步公开证书与元数据。

恢复凭据不放入订单备注、邮件正文或普通日志。PIN 初始化不得由后台默默设置固定默认值。

### 8.2 资源权益必须在 API 层执行

- 建卡数量、证书容量、密钥生成权限、允许区域、订阅到期等不只约束门户表单。
- 旧 `POST /api/cards`、密钥生成和证书导入入口也要经过权益与权限校验，避免绕过商城无限创建。
- 既有云卡保留并标记为历史资源，迁移时不擅自收费、删除或强制到期；运营可显式指定后续策略。
- 云卡到期与暂停默认保留证书和审计数据，限制新建/敏感使用的具体策略须预先发布；所有入口一致执行。到期不等于自动吊销卡内证书。
- 云卡续费延长订阅；失败重试与延长时间均幂等。长期未续费的数据保留/销毁策略另行明确，不做静默删除。
- 管理员不能只通过选择 `hsm` 就售卖“硬件保护”；真实驱动与实测未完成时禁售该规格。

## 九、交付与客户端对接：纳入主版本的必需工作

### 9.1 四条交付路径

| 路径 | 私钥位置 | 用户得到什么 | 必须补齐 |
|---|---|---|---|
| 用户自备 CSR | 用户设备/服务器 | 证书与证书链，不含私钥 | 申请链路接受和验证 CSR，签发后匹配公钥 |
| 允许导出的文件交付 | 策略允许的服务端生成/保存 | 真正的加密 PFX，或明确授权的其他格式 | 正确编码、密码、安全授权、交付审计和次数策略 |
| 云卡远程使用 | 云端 | 云卡绑定关系、公开证书、远程签名能力 | TOTP、云卡发现、PIN 会话、元数据同步 |
| 不可导出设备制钥 | 实际支持的 TPM/实体设备 | 回装到原密钥的证书 | 硬件能力确认、设备内签 CSR、证书公钥匹配与回装 |

**禁止使用“云端私钥下载 → 导入 TPM”冒充“私钥从未离开硬件”。** 不可导出路径失败时必须明确失败，不自动退化为软件制钥或可导出套餐。

### 9.2 对 `17` 报告任务的吸收

| 报告项 | 本方案处理 | 验收点 |
|---|---|---|
| P0-1 下发接口不存在 | 补兼容接口并统一交付授权；同步修复真 PKCS#12 | 客户端可接收授权材料；禁止导出时服务端拒绝 |
| P0-2 PIN 会话缺失 + 第五章 P1-1 PIN 语义 | 账号登录和卡片登录彻底分开；`C_Login` 使用卡 PIN | 有 PIN 的云卡能签名；错误/锁定/到期各自正确提示 |
| P0-3 TOTP 缺失 | 云账号登录实现二阶段状态，不接受空 token 为成功 | 启用 TOTP 的用户在客户端与门户均可正常登录 |
| 第七章 P1-1 安全等级 | 服务端决定允许策略，客户端报告实际能力，取两者交集 | 不能通过本地改等级或软件回退绕过硬件约束 |
| 第七章 P1-2 元数据 | 扩模型并实现新增、更新、移除/失效对账 | 续期、吊销、移除后界面与操作一致 |
| 第七章 P1-3 Token | 登录、TOTP 完成、刷新统一到期时间与失败语义 | 过期可恢复；不使用过期 token 无限刷新 |
| 第七章 P1-4 云卡管理 | 接通 `ListCards`，补必要 PIN/PUK 与证书操作入口 | 用户无需手填 UUID；敏感动作遵守权益和授权 |
| P2-4/P2-5 | HTTPS 与实际使用算法的机制对账前移 | 生产不走 HTTP；签名可独立验签，RSA 解密结果正确 |

报告中的设备注册、心跳、远程命令队列、审计上报和云 TOTP 聚合不作为此次必需项，避免把门户项目扩成设备管理平台。

### 9.3 认证、PIN 与错误契约

- 服务端普通登录、TOTP 完成、刷新响应统一包含 `token`、`expires_at` 及必要用户信息；TOTP 挑战响应与成功响应必须使用可区分结构。
- 客户端账号凭据/令牌安全存储，不把平台密码放进卡 PIN；账号过期先处理账号重认证，涉及 TOTP 时必须等待用户完成，不自动绕过。
- 卡 PIN 会话短期驻留内存，绑定用户、卡片和服务来源；退出、锁定、重置、账号切换时清理。
- 现有 PIN API 实际成功字段为 `pin_session_token`、`expires_at`、`ttl_seconds`，另有 `success`、`remaining`；统一两端类型，不能沿用不匹配的 `session_token/expires_in` 假设。
- 错 PIN 不做循环重试，避免消耗全部重试次数。单纯会话过期提示重新授权，不直接等同 PIN 错误/锁定。
- 前端 HTTP 层区分账号 401 与 `X-PIN-Required`；卡 PIN 过期不能清空账号并跳登录。补齐相关请求/响应头的 CORS 白名单。
- 本地 PKCS#11/KSP 错误按真实原因映射；只读操作、签名、解密分别验证，不把 ECDSA 当作可解密算法。

### 9.4 下载与下发授权

推荐保留 `17` 报告方案 A 的兼容路径 `POST /api/certificates/{uuid}/download`，但它仅用于**策略允许的私钥下发**，不能成为任何账号都可用的通用导出入口。

- 兼容响应覆盖 `DeliveredCert` 所需的 `cert_pem`、`key_pem`、`chain_pem`、算法及证书元数据；不可导出时返回稳定业务错误。
- 公开证书/证书链读取与私钥交付拆开；一般证书列表不携带私钥。
- 授权以证书所有者、订单权益、绑定模板、真实交付方式和有效二次授权共同判断；管理员角色不自动获得所有用户私钥导出权。
- 无卡证书按证书归属授权；不能继续因为 `card_uuid` 为空而拒绝合法用户，也不能因策略字段为空就默认允许私钥导出。
- `allow_reimport`、`cloud_backup`、`allow_reissue`、`max_reissue_count` 分别解释，不把“备份存在”当成“允许向用户导出”。
- 复用并完善 `CheckReissue`、`RecordReissue`、下发记录和计数器，绑定真实证书与模板；检查、额度预留和请求幂等不能分成可竞争的裸操作。
- 下发次数按实际敏感材料释放语义计数，不无限等待不可信客户端回执；下载重试/网络中断有明确的短期幂等恢复规则，不能造成无限补发。
- PFX 密码经受保护 POST 请求体提交，不放 URL；敏感响应使用 `no-store`，日志/错误/审计禁止记录私钥、密码和会话 token。
- 证书内容先识别 PEM/DER 并规范化，避免二次 PEM 包装；PFX 必须能被独立工具及客户端实际解析。

### 9.5 浏览器与桌面端跳转

默认使用“客户端打开系统浏览器进入网站；网站提供下载与绑定指引；客户端自行登录后拉取资源”的可靠方式。

同站共用登录不等于桌面端与浏览器自动单点登录。不得把 JWT、密码、PIN、私钥放进跳转 URL，也不假设自定义协议、设备 agent 或浏览器访问本地端口已经存在。后续若增加一键唤起，使用短时、单次、绑定目标的交接凭据，并独立评审。

## 十、CA、CRL、OCSP 与 CSP 服务页面

### 10.1 公开信任服务中心

- 管理员选择公开发布的 CA，展示名称、用途、层级、有效期、状态和证书指纹；内部 CA 默认不出现在公开目录。
- 提供根/中间 CA 证书与完整链的明确下载按钮，标明 PEM/DER 格式和适用方式。
- 每个 CA 展示实际配置的 CRL 下载地址、最近生成时间与下一更新时间，以及 OCSP responder 地址和使用说明。
- OCSP 是协议服务地址，不是普通浏览器页面；有地址不等于响应正常，未启用或配置错误需准确展示。
- 对外地址从经验证的公共 Base URL 与服务配置生成；不得暴露 `localhost:1027`、随意信任 Host 或把后台模板接口整体匿名开放。
- 已公开的 AIA/CRL/OCSP 链接需保持长期稳定；已签发证书中的地址不能随网站换路由失效，历史 CA 保持必要的下载与吊销材料可获取。
- 若展示 ACME，先验证目录及实际支持流程；不公布当前未实现的协议能力，不开放绕过订单/账户权益的付费产品签发通道。

### 10.2 CSP/KSP、驱动与部署帮助

用户所说“CSP 页面”暂按 **Windows CryptoAPI CSP / CNG KSP 接入说明** 理解；同时区分证书服务常用的 CP/CPS 文档，不混用缩写。

- `/integrations/csp`：说明 CSP、KSP、PKCS#11 的用途差异、现有 OpenCert 组件、安装步骤、兼容应用和排错入口。
- `/downloads`：客户端、驱动、支持平台/架构、版本、发布时间、校验值、安装与卸载说明。
- 不凭 `clients/` 中的 CSP 扩展字段宣称已有传统 CSP DLL；具体支持以 `drivers/` 产物和应用实测为准。
- 证书 CP/CPS、服务条款、退款规则等如需公开，提供独立文档入口、版本与发布日期，由运营审核发布；不生成虚假的认证或合规结论。
- 浏览器不负责直接安装驱动、写入系统信任库或静默导入私钥；敏感系统操作由用户在客户端确认执行。

## 十三、构建、迁移与发布

### 13.1 前端发布

- 延续 React + Vite + Ant Design，不为门户引入另一套 Next.js/SSR 服务。

- Go SPA 回退仅用于前端页面路径；缺失 JS/CSS、未知 API 和 PKI 协议请求返回正确错误，不能全部回 `index.html`。
- 默认使用同源 `/api`，保留可选 API Base URL；不能将线上浏览器指向使用者电脑的 `localhost:1027`。
- 统一 Vite 代理、Go 路由、构建脚本与容器产物；直接刷新产品页、控制台深链接应可访问。
- 基础 SEO（页面标题、描述、公开链接、站点地图）属于门户发布项；需要搜索引擎完整抓取时评估静态预渲染，不在本次默默更换技术栈。

### 13.2 数据迁移

- 使用增量、可重复执行的迁移，保留用户、CA、证书、云卡、余额和旧订单；迁移前备份，失败有可诊断错误。
- 已有申请模板可经管理员预览转换为商品草稿；默认不自动上架、不自动收款。
- 旧订单标记为 legacy 并保留原快照；历史金额和已付款事实不得按新价格重算，也不能再次扣款。
- 旧无明确导出策略证书需明确迁移规则；敏感导出默认不因空字段放行，避免一次迁移扩大权限。
- 如保留历史匿名申请，仅作为待人工核对记录；必须完成真实账户认领和验证后才进入新流程，不能把邮箱字符串直接当作可信用户 UUID。
- SQLite、PostgreSQL、MySQL 的迁移、条件更新、唯一约束和事务行为需分别验证，不能以一种数据库成功代表全部支持。
- 实施前重新核对工作区已有未提交改动，采用定点修改，不覆盖 `17` 报告或其他并行开发内容。

## 十四、实施顺序与验收门槛

所有阶段当前均为**计划，未开始实现**。阶段用于控制依赖，不意味着可以把未完成交付的商品提前上线收费。

| 阶段 | 内容 | 交付门槛 |
|---|---|---|
| P0 契约与基础修复 | 统一 DTO/角色、订单权威定价、资金/状态机设计、导出策略、部署路由；明确各能力开关 | 关键接口不再接受客户端改价/改付款状态；迁移和兼容策略可验证 |
| P1 门户与运营配置 | 首页、分类/详情、购买配置、注册回跳、商品/SKU/云卡模板、系统用户管理 | 管理员发布真实可用商品，访客能比较并登录恢复配置 |

| P3 云卡与客户端闭环 | 云卡开通/订阅、TOTP、PIN、发现绑定、元数据同步、授权下发、必要机制对账 | 有 PIN、启用 TOTP 的账号能够在客户端使用已购云卡并完成独立验签 |
| P4 服务门户与整体发布 | CA/CRL/OCSP、下载/CSP 指引、通知、旧链接、生产资源发布和综合验收 | 原始需求全覆盖，无虚假能力展示；发布可回退且历史资产可用 |

### 14.1 关键验收用例

| 编号 | 场景 | 预期 |
|---|---|---|
| A01 | 未登录浏览/选规格，注册并完成 TOTP | 保留非敏感配置；未完成登录前不能创建订单 |
| A02 | 管理员设置价格、数量、时长、开通模板并发布 | 门户展示与服务端报价一致；停用规格不能购买 |
| A03 | 篡改价格、模板、用户 ID、付款状态 | 服务端拒绝或重新按权威数据计算，不产生越权资源 |
| A04 | 余额不足或重复点击付款 | 不扣负、不重复扣款；用户可改选直付 |
| A05 | 回调重复、金额/币种/渠道不符、换渠道后双付款 | 不重复记账/履约，异常可追踪与退款 |
| A06 | 库存只剩一份并发下单、订单过期后迟到付款 | 不超卖；库存和到账有明确补偿路径 |
| A07 | 一次购买多份证书、其中一份需补资料 | 每份权益独立，主单显示部分进度，不重复消费 |
| A08 | SSL/邮件/代码/文档签名不同用途申请 | 字段与验证按模板生成；不能套用同一域名表单 |
| A09 | 未验证、材料过期、CSR 签名错误、算法不允许 | 不得签发；可定位原因并继续补正 |
| A10 | 审批重复、签发后进程退出、网络超时重试 | 不多发证书；恢复同一任务/结果，必要时进入人工核对 |
| A11 | 下载无卡证书、PEM/DER/PFX 导出 | 合法归属可下载；格式可独立解析，PFX 密码实际生效 |
| A12 | 私钥不允许导出、超次数、并发下发 | 所有入口执行同一策略；无越权导出或额度穿透 |
| A13 | TOTP 云账号 → 发现云卡 → PIN 登录 → 驱动签名 | 实际能用；签名可用证书公钥验证 |
| A14 | PIN 错误/锁定/会话到期、账号 token 到期 | 区分提示，不清空错误的会话、不循环尝试 PIN |
| A15 | 证书更新/吊销、云卡移除、服务到期 | 客户端同步状态；在线敏感操作由服务端及时限制 |
| A16 | 硬件不可用或软件回退 | 不授予硬件保护标签，不静默转成可导出路径 |
| A17 | 第三方原路退款、余额退款、部分退款失败重试 | 真实退款结果与页面一致，无重复退款/退款超额 |
| A18 | 普通用户访问他人订单/证书；操作员访问用户管理 | API 拒绝，不能只靠页面菜单隐藏 |
| A19 | 公开 CA/CRL/OCSP 地址与驱动下载 | 无内部地址；正确内容/MIME；未发布资源不泄露 |
| A20 | 生产构建、深链接刷新、旧页面和协议路径 | SPA 可访问，API/协议不被 HTML 回退覆盖 |

工程验收还包括：两端前端构建、Go 编译/测试、核心服务契约与集成测试、真实 PFX 解析、独立签名验签、支持数据库的迁移/事务测试。支付至少完成实际启用渠道的沙箱或授权测试；硬件规格必须实机确认。**编译通过不等于业务验收通过。**
