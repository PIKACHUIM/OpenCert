## 3. 已有实现与测试证据

### 3.1 门户、订单与证书履约

**源码可见：** 服务端路由已覆盖门户产品/规格、报价、订单、付款状态、退款申请、证书申请上下文和管理员商品操作。门户与控制台页面及申请向导组件也已存在。此结论只说明相关代码和调用入口可定位。

**测试有断言：** `servers/test/api_business_test.go` 包含真实 HTTP 测试环境，文件头列出商品配置、证书销售申请、SAN 限制、订阅额度、优惠码及服务端 API 行为；`servers/test/portal_test.go` 覆盖商品校验、公开可见性、报价和登录/模板前置条件。本文未执行这些测试。

**尚未证明：** 已启用的真实支付渠道能够收款、回调公网可达、第三方退款完成、生产迁移安全，或端到端业务状态全部正确。服务端存在支付渠道实现和回调/退款路由，不等同于商户配置与实网验收。

### 3.2 客户端云卡认证、PIN 与下发

- `clients/internal/card/cloud/client.go` 识别 TOTP 挑战并拒绝空 Token；实现 TOTP 完成、云卡 PIN 校验、短期会话缓存及敏感请求头。
- `clients/internal/card/cloud/slot.go` 区分平台账号登录与云卡 PIN，并保留 TOTP 等待状态。
- 服务端注册了 `POST /api/certificates/{uuid}/download`。私钥下发路径检查证书归属、硬件不可导出、签发时密钥存储策略、格式和额度，并在返回私钥前记录下发。
- 客户端 `clients/internal/api/cloud_handler.go` 提供本地 `/api/cloud/deliver`，支持落入本地 PKI 证书库或导入本地卡；`clients/front/src/pages/Certs/index.tsx` 中有下发向导入口。
- `clients/test/cloud_auth_test.go` 对 TOTP、PIN 和下发契约使用 `httptest` mock；它不是服务端真实处理器与客户端之间的集成测试。`servers/test/delivery_test.go` 覆盖真 PKCS#12 编解码及申请前置校验，但当前文件未见针对上述交付 HTTP 路由的测试函数。

**需进一步验收：** 服务端交付策略的 HTTP 集成断言、权限与额度竞争、硬件密钥拒绝、缓存头/审计、客户端持久化交付与失败恢复，以及真实客户端—服务端签名验签链路。

### 3.3 云端证书同步边界

`clients/internal/api/cloud_handler.go` 当前 `doCloudSync` 的输入是本地 SQLite 中已经存在的 Cloud Slot 卡片，并通过其 `CloudCardUUID` 请求证书列表。代码为既有证书新增或更新公开元数据（包括主体、有效期、CA 和吊销状态），并且在新增时通知 Slot 变更。

该流程不请求远端 `/api/cards`，因此目前的“同步”不是远端云卡发现、自动绑定或完整删除/失效对账。`cloud.Client.ListCards` 虽然存在，但静态调用链没有把它接入上述同步流程。同步时通过 `cloud.NewClient(..., true)` 创建客户端，允许非 HTTPS URL；TLS 证书校验并未被关闭，但生产环境强制 HTTPS 尚未由该调用路径保证。

### 3.4 私钥存储与硬件边界

- `roadmap/19-KEY-STORAGE-BACKENDS.md` 与 `servers/internal/keybackend/` 描述 database、TPM、PKCS#11 后端及不可导出策略；存在 PKCS#11 与 storage-zone 相关测试代码，但测试未运行、硬件未实测。
- 私钥后端字段、驱动选择或策略配置不代表实际设备提供商已安装、密钥已在设备内生成，或硬件不可导出属性已由设备端证明。
- TPMSC 是 Windows TPM 虚拟智能卡路径，不能与 `clients/internal/card/tpm2/` 的 TPM2 Slot 混为一谈。
- 当前 `tpmsc.CreateCard` 通过 `tpmvscmgr.exe` 的 `DEFAULT` 参数建卡，并在结果中提供固定初始 PIN/PUK/Admin Key；`tpmsc.Slot.Login` 仅更新本地登录标志。建卡默认凭据、凭据轮换提示和真实验证均须纳入安全验收。
- `tpmsc.Slot.FindObjects` 仍标记 TODO；`Sign`、`Decrypt` 返回要求通过 Windows CSP/CAPI/CNG 调用的错误。这意味着当前代码尚未提供可由该 Slot 完成的对象枚举与密码操作。
- TPMSmartCard 交付资料建议复用 OpenCert 客户端而非维护第二套 UI；`.tsb v2` 的设计/交付边界需按原方案保持同一 TPM 限制，不得把它描述为跨设备恢复。相关真机建卡、证书导入、备份/还原验收没有在本次执行。

## 4. 相对需求的主要差距

| 优先级 | 差距 | 影响与验收边界 |
|---|---|---|
| **P0：发布前阻断** | 安全关键链路仍只有静态或 mock 证据 | 对 TOTP/PIN/下发、真实 PKCS#12、归属及次数限制、错误恢复补服务端集成与跨端验收；测试文件存在不等于测试通过。 |
| **P0：发布前阻断** | 工作树包含大量未提交用户改动 | 在发布/合并前需由项目维护者审阅并决定纳入哪些更改；不得将当前工作树等同于可复现的 release commit。 |
| **P0：发布前阻断** | TPMSC 固定初始凭据及功能缺项 | 完成安全初始化/改 PIN 策略，消除默认凭据暴露风险；实现或明确禁用对象枚举、签名/解密入口，并用 Windows 实机验证。 |
| **P1：云卡闭环** | 缺少云卡商品开通模板与资源订阅权益的 API 强制执行证据 | 现有 `promo_subscriptions` 管理证书申请额度，不是云卡配额、容量、服务期或到期限制。商品页面不能代替建卡/签名等 API 的权益控制。 |
| **P1：云卡闭环** | 客户端尚无静态证据表明会发现并绑定用户的远端云卡 | 当前同步只处理已映射卡；需接入 `ListCards` 与选择/绑定流程，避免用户手动猜填 UUID，并验证映射归属。 |
| **P1：跨端验收** | 服务端下发 HTTP 路由缺少对应集成测试证据 | 覆盖无权访问、无托管私钥、硬件不可导出、模板不允许、额度耗尽/并发、真实 PFX 和成功审计；再联调客户端两种下发目标。 |
| **P1：云端安全** | 若干客户端路径允许 HTTP | 云端同步和下发等路径使用 `allowInsecure=true`；生产应明确拒绝非 HTTPS，并对真实证书/系统时间与错误状态验收。 |
| **P1：系统集成** | PKCS#11 驱动作为真实调用方的完整 E2E 尚未证实 | 需从驱动调用枚举、登录、查找、签名，到服务端/本地 Slot 完成操作，再对签名独立验签。 |
| **P2：运营与迁移** | 通知和历史数据迁移等未有当前完成证据 | 对照 `roadmap/18-PORTAL-COMMERCE-DELIVERY-PLAN.md` 的支付/审核/到期通知、旧匿名申请认领、legacy 订单和模板迁移逐项验收。 |
| **P2：增强项** | CP/CPS 发布、在线验签、多币种、购物车等仍属待排期增强 | 不应阻塞已明确范围的主链路；任何面向客户的能力承诺必须先有真实实现与验收。 |

## 5. 建议后续路线

以下是按依赖和风险排序的建议，不代表相关测试已执行，也不授权改动当前用户未提交文件。

### 阶段 A — 固定可复现基线

1. 维护者先审阅当前 `git status` 中的未提交文件，确定工作树快照及纳入范围；不要在文档或修复过程中覆盖这些改动。
2. 由维护者选定干净分支/提交作为验证起点，记录 Go、Node、数据库与操作系统版本。
3. 分别运行客户端、服务端及两个前端的现有测试/构建，并记录实际失败与通过项；本次基线没有运行它们。

### 阶段 B — 云卡安全与端到端交付

1. 为服务端私钥下载路由增加/补齐 HTTP 集成断言，覆盖归属、模板、硬件不可导出、下发额度、PFX 解析及失败不泄露。
2. 运行真实客户端—服务端 TOTP → PIN → 签名流程，并对签名独立验签；确认刷新/过期、错误 PIN、PIN 锁定和退出清理。
3. 完成云卡列表发现、绑定与同步对账；确认无归属卡不可绑定，证书续期、吊销和移除状态会正确反映。
4. 对生产客户端调用强制 HTTPS；确认敏感响应 `no-store`，密码、PIN、Token 和私钥不进入 URL、日志或持久化缓存。

### 阶段 C — 云卡权益与支付履约

1. 单独定义云卡 SKU、开通模板、订阅/配额、到期与暂停策略；不要复用证书申请订阅额度冒充云卡权益。
2. 将权益校验落实在所有建卡、密钥生成、证书导入和敏感使用 API，并测试并发、重试、到期和既有云卡兼容。
3. 由运营/部署提供真实支付渠道与商户配置后，再做沙箱/授权测试、回调金额与幂等、退款结果及异常对账验收。

### 阶段 D — TPMSC 与驱动发布门槛

1. 实现安全的初始凭据配置/轮换与真实 PIN 校验语义；移除默认 PIN/PUK/Admin Key 成为可直接使用凭据的路径。
2. 实现或显式禁用 TPMSC 对象枚举、证书导入/删除、签名和解密；用 Windows 实机确认 CSP/CNG 与 TPM 行为。
3. 完成 `.tsb v2` 同 TPM 备份/还原约束检查，并按融合方案验证“建卡—导入 PFX—证书可见—删除/还原”。
4. 完成驱动到 client-card 的真实 E2E 与独立签名校验后，才能宣称 PKCS#11 集成已验收。

### 阶段 E — 运营收尾

1. 核对通知、数据迁移、发布资源与公开服务链接；生成迁移回滚与数据备份方案。
2. 更新 `roadmap/11-ROADMAP.MD` 的阶段状态，或建立新的唯一进度追踪入口，避免保留多个相互矛盾的完成百分比。
3. 只在上述验收证据齐备后更新发布状态、生产可用声明和对外商品承诺。
